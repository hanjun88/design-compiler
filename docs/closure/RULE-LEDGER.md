## Dispositions

- **KEEP_IN_SKILL** — Already the skill's own knowledge; stays, but must be registry-backed (rule_id/decision_id/provenance/confidence) and every documentation copy must be generated from, or verified against, the registry.
- **MIGRATE_TO_SKILL** — Aesthetic knowledge that currently lives in design-compiler. Moves into the skill rule registry with provenance; the compiler-side literal is deleted.
- **DELETE_DUPLICATE** — A second copy of a value/definition that already has a canonical home. Deleted (or turned into a generated reference); never reconciled by averaging.
- **DERIVED_RUNTIME_ONLY** — A runtime number the compiler still needs. It is no longer authored in the compiler: it arrives through the AestheticConstraintSheet, carries source_ref -> rule_id -> decision_id, and is lint-checked.
