# 依恋×共情机制

## R — Reading
来源 `legal_open/PMC10233954.txt`（PMC 开放获取元分析）
- L00002–L00027: 元分析显示安全依恋促进共情能力；回避依恋抑制共情（情绪去激活同时关闭了对他人情绪的雷达）；焦虑型共情呈两极摆动——有时过度共情求接纳，有时因自身痛苦过载而关闭。

## I — Interpretation
依恋风格不只是"你怎么求亲近"，也是"你怎么接收伴侣的情绪"。安全型：情绪雷达在线，可承接伴侣痛苦而不被淹没。回避型：去激活脚本同时关闭了自己的情绪和对伴侣情绪的雷达——"她哭了我不知道该怎么办"不是冷漠，是雷达被关掉了。焦虑型：雷达过载——既可能过度共情（把伴侣的痛苦当成自己的），也可能在自己痛苦过载时突然关机。理解这点能避免把"他没反应"翻译成"他不爱我"。

## A1 — Application Example
**合成演练**（基于 PMC10233954 元分析结论）：
1. 伴侣表达痛苦时，观察自己的反应：想靠近？想逃？想讲道理？想关掉？
2. 标注反应类型：雷达在线 / 雷达关闭 / 雷达过载；
3. 若关闭：不强迫自己共情，先命名"我现在接不住，让我坐 5 分钟"；
4. 若过载：先把自己情绪落地，再回到伴侣。

## A2 — Future Trigger
- 场景："他为什么对我的痛苦没感觉" / "Why can't he just comfort me?"
- 语言信号："你根本不在乎我" / "你就是冷血"
- NVC 提示："他现在不是不想安慰你，他的共情雷达可能被去激活脚本关掉了。你越逼他'你为什么不说话'，他的雷达关得越紧。试试：'我不需要你马上解决，我只需要你坐在这里 5 分钟，听我说'——把任务降到雷达能承受的功率。"
- 与相邻能力区分：`deactivation-strategy` 处理"我为什么想逃"；本卡处理"我为什么接不住对方的情绪"。

## E — Execution
| 步骤 | 输入 | 完成标准 |
|---|---|---|
| 1. 当下反应 | 伴侣表达痛苦 | 命名反应（靠近/逃/讲道理/关机） |
| 2. 雷达状态 | 上述反应 | 标注在线/关闭/过载 |
| 3. 降功率请求 | 对伴侣 | 1 句"我需要的最小动作"（坐 5 分钟/倒杯水） |
| 4. 回归 | 自己状态恢复后 | 1 句回到伴侣的话 |

输入：一段"他不共情我"的抱怨。输出：反应标注 + 雷达状态 + 最小动作请求 + 回归句。

## B — Boundary
- 反场景：把"他共情雷达关闭"当成虐待的借口。
- 失败模式：用依恋框架无限容忍情感忽视。
- 作者盲点：共情差异有神经基础，但长期训练可以改善；不能当静态标签。
- **安全红线**：情感忽视若伴经济控制、社交隔离、威胁，不再是共情问题，转安全评估。
